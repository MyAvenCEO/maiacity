# Query creation-metadata prefilter

The universal query previously called `meaning` for every local entry before testing the type/label plan. Meaning computes current tags and policy-derived semantics; for drafts its landed check can hydrate deferred history. A typed active view therefore paid that cost for unrelated entries before pagination.

This change scans only canonical metadata to prefilter by requested vault and immutable creation labels before meaning/record work. The current selector's tag predicates are removed from this conservative candidate plan: creation tags cannot safely reject an entry whose tags changed later. Full authorization, current selector, schema translation, record predicates, ordering, exact count, unresolved-candidate readiness and pagination remain unchanged. There is no new persisted index/cache or invalidation protocol. Metadata scanning remains O(local entries); the expensive meaning/materialization work is limited to plausible candidates. A limit cannot be pushed ahead of predicates and ordering without changing exact counts and results.

Lean `QueryCandidates` proves stable filtering and pagination equivalence assuming the candidate predicate has no false negatives. That assumption is implemented by retaining immutable type/author/id/creation-time tests and dropping mutable tag tests. The Rust selector regression varies creation/current tags. A differential query regression adds96 unrelated entries and compares the complete response against the former full-scan candidate source across mixed predicates, updated tags, sorting, pagination and an unauthorized peer.

Validation pending compiler availability: `cargo test -p avendb --lib creation_candidate_regressions`; `cargo test -p avendb --lib query_creation_plan_tests`; existing `cargo test -p avendb --test engine a_query_picks_by_labels_then_tests_what_it_opens`. Lean source proof checked directly with the pinned toolchain. No new latency claim is made without runtime measurement.
