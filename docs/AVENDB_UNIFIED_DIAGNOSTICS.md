# Unified device diagnostics

Implemented in this change: the global top-left dialog has Run diagnostics and Copy logs, plus dismissal. The report is usable while locked. Existing startup/unlock and lifecycle instrumentation is collected automatically; independent bounded landmark lists preserve early evidence after noisy sync/navigation. Local operation failures retain only fixed reason classes. No raw error text, operation arguments, entry content, peer IDs, or addresses is copied.

Run diagnostics arms the existing two-minute peer policy and reactive-consumer observers, without creating messages or other domain entries. It reads a local world summary and current network/performance counters, measures foreground event-loop delay, and runs bounded credential-free HTTP probes (2 HTTP RTT samples, 4 MiB Maia range download when a verified release asset is available, 8 MiB Cloudflare download, 1 MiB upload). The overall run aborts at45 seconds; individual transfers abort at8 seconds; engine reads time out at5 seconds and a still-pending read prevents duplicate enqueueing. Closing/hiding the dialog cancels further work. Opening the dialog refreshes peer observations with bounded engine reads, repeating at most24 times at5-second intervals while visible. Copy logs immediately exports the latest captured report and retained local evidence without awaiting engine reads, preserving iOS clipboard activation. A selected readonly textarea supports manual copy when clipboard access fails.

The JSON includes exact frontend commit when configured, separately identifies the hosted release queried, and explicitly leaves native-engine identity unavailable rather than conflating it with the web release. Passive scoped-query observations contain readiness enums and row/pending counts only. Manifest scheduling counts are not proof of completeness.

For physical acceptance: run on both devices, perform ordinary edits, copy logs on both while the observers are active. Consumer observations are not rendered-frame or durable-save acknowledgements; HTTP Mbps is not avenDB useful throughput or maximum link bandwidth. Missing samples are unmeasured. A reload with no exit event does not establish memory pressure or any other cause. iPhone stability and cross-device latency still require physical testing after deployment.

Validation: focused runner privacy/session/locked/cancel/network-range tests; durable oldest-unlock and lifecycle-landmark regressions; existing query-window/journal/local timing tests; Svelte compilation and strict TypeScript checking of changed telemetry modules. The standalone static network-only tool remains available for older links, but the global dialog never navigates to it.
