# One held-log pass for world file metadata

An offline native sample on the installed 30d556c8 app showed full-world snapshot capture spending its active samples in `Lab::entry_files`. That function scans the device's held edits for one entry. Calling it for each world row repeated the same history traversal, while snapshot capture held the shared Lab mutex. Moving JSON encoding outside that mutex had not removed this work.

The focused fix groups roots for the already selected world entries in one pass. Each group retains receipt order and the first occurrence of each root. It then uses the existing `Lab::file` lookup on the current device to resolve plaintext lengths. The grouping is temporary snapshot work, not a persisted index, permission source, or independent cache. Its vectors and deduplication sets are bounded by the selected entries and their unique held roots; unrelated roots are never collected. The world row order remains unchanged. Full-world row selection and every other field retain the canonical implementation. Narrow `entry_views` reads retain their early filtering and per-entry behavior.

`avendb/spec/AvenDB/EntryFilesBatch.lean` proves that selecting a grouped entry yields the original ordered scan, and therefore identical results under the same deduplication/length-resolution operation. This is an abstract algorithm contract, not an extracted proof of Rust containers. Native differential tests connect the implementation to the original scanner. They cover selected/empty scopes, interleaved file roots and duplicates, current device views, revocation and restore, and real assets before and after sync. A deterministic iteration counter ensures a batch traverses held history once, with no traversal for an empty selection.

This removes repeated history visits from full-world file enumeration. It does not move all snapshot construction outside Lab, eliminate the remaining single pass, fix authorization replay, or establish physical sub-50 ms UI latency. Record/history materialization and authorization preparation remain separate measured work. BatteryCube eventually rendered offline during acceptance; its earlier blank was a loading observation, not proof of a permanent renderer failure.
