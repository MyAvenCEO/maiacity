## Problem and scope

The existing targeted `get`/`room` observer can update before a background world summary. Actual Todos still derived its rows from `world.entries`; local writes waited for that expensive summary, and remote changes also faced an unconditional `max(150ms, 2 × previous refresh duration)` delay. The existing generic-status browser fixture used a targeted `get`, so it did not cover the real collection view.

The new `entry_views` read takes exactly one scope: `vault`, or `entries` (an explicit array of at most 512 IDs, deduplicated and sorted), and optional array `types`, canonical `kind`, and metadata actor `as`. It returns `{ok:{rows:[...],totalEntries,readableEntries}}`, or the ordinary refusal/null result. Rows use the same landed entries, device-visible meanings, and **single canonical EntryView JSON projection** as full world. Unknown/empty vaults return no rows. Types filter only labels already known to the device. Kind filters match the canonical world classification, including custom-labeled todos. Counts preserve empty/unreadable-vault semantics without opening unrelated record bodies; `as` selects metadata only and grants no authority. Sealed metadata stays sealed. The operation never grants authority or synthesizes a record from a mutation request.

Every entry field remains identical to world: readers, writers, sharers, levels, authors, record/lens presentation, deletion state, files and entry/file `syncedTo`. The node supplies the same holdings projection, copying and iterating only selected logs/files. Shared reach is an immutable Arc snapshot, not a copied authorization cache. Owned row JSON encoding runs outside Lab on a separately bounded collection lane. The Rust differential regression compares selected rows to full world before/after sharing, revocation and deletion, across owner, unrelated and relay devices, with nonempty entry/file holders. Malformed vault/types and unknown fields are refused.

Todos mounts one existing `api.observe` subscription for its selected vault. It receives authoritative rows independently of full-world pacing; it clears failed/refused results and disposes with the component. Existing query/device/context scope handling suppresses stale answers. Vault/share navigation metadata still comes from world. This adds no persistent cache, optimistic success state, chat-specific path, server authority, or new write semantics.

## Lean-first boundary

`AvenDB/LocalWrite.lean` models collection rows as an exact selection from an authoritative projection: a selected row retains its canonical fields, and collection result selection is independent of full-summary readiness. The model passed before implementation; it does not extract Rust/JS or prove authorization, filesystem durability, browser paint timing or performance. Native differential tests and the actual component regression establish the separate implementation correspondence.

## Targeted Story and Note follow-up

Explicit-ID scope looks up the canonical policy index rather than scanning unrelated bodies. IDs can span vaults; every selected row uses its own vault's audience/levels and the existing canonical mapper. Unknown IDs are omitted, empty lists are valid, and malformed/oversized/ambiguous scopes are refused. `as` only selects readable-count metadata; it cannot grant access. The Lean explicit selection theorem proves returned rows remain members of the canonical authorized projection; the bound is specified separately. Native differential coverage compares selected rows and counts across vaults and actors before/after access changes.

Story and Note observe selected canonical metadata and their note/history operations through the shared reactive reader, independently of full-world refresh. Each observer scope owns one existing demand lease, reused on revisions and released on replacement/close. These are scheduling hints, not another record/auth cache. Unsubmitted drafts survive authoritative refresh; changing entries resets line-local editor state. Related cross-vault flow and copies metadata still uses the existing world view and is not silently narrowed to the active vault.

Validation is tracked in the handoff: actual-component synthetic-worker browser checks establish scheduling/render behavior, not native latency or a physical <50ms guarantee. New Rust source requires exact-head remote native checks and regenerated production WASM before deployment.
