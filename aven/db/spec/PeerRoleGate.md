# Provider-role neutrality: blob-gate regression

The two `PeerRoleGate.lean` corollaries were checked before adding the runtime regression. They reuse `Logs.lean::Node.hands` (T27): equivalent current histories and authenticated connections produce equal gate answers; an authenticated requester without current file permission is refused. The model does not contain a deployment-role override. This does not prove all server services interchangeable or make missing connectivity available.

Runtime correspondence is `avendb-net/tests/files.rs::revoked_blob_requests_are_refused_by_server_and_ordinary_peer_alike`. The fixture uses an ordinary owner Mac, an explicitly authorized ciphertext-backup server and Carol's reader device. Raw blob reads of an initially granted file succeed at both providers. The owner revokes Carol's grant, then attaches a distinct new file. Both providers must physically hold its bytes while their current file permission for Carol is false. Carol names the new hash directly through iroh-blobs, bypassing its application checks; neither provider may hand it over. Carol gains neither the file key nor the whole file.

The post-revocation file avoids an unsupported claim that previously disclosed bytes or historical authorized content must be erased. Both positive and negative branches use the same node identities/endpoints; no node is recreated to clear prior authority. The test does not require reuse of an individual blob stream, which each request opens anew.

Immediately before each negative request the reader completes authenticated sync and the provider identifies that endpoint as the expected signer. Raw blob connection establishment must succeed; only then may the request fail, and its disposable receive store must lack a complete blob. This prevents a connection-establishment failure from passing as denial. The test observes protocol-request failure alongside explicit current permission denial, not a newly introduced wire error classification.

This expands the existing file suite's server-only initial-permission checks with changed permission and ordinary-provider parity. It does not change production authorization, master-recovery ownership, retirement freshness gates, carrier configuration, or wire formats. Physical server absence, relay loss and broader hostile-peer behavior remain separate acceptance work.

Before storing the distinct new bytes, the test explicitly observes the known grant as no longer live at both providers. This matters because `store_file` also updates physical holdings and can notify peers; it is not sufficient to delay only the entry write. The initial authorized root and new root must differ.

Existing complementary coverage is `avendb/tests/keys.rs::t27_files_follow_their_edits` (reader/relay/outside permission and encrypted-file keys), `revoked_reader_cannot_open_new_edits` (new epoch denies revoked readers while their old content remains readable), and `avendb/tests/split.rs::mceliece_keys_go_only_within_reach` / `announcements_tell_each_peer_of_its_own_logs_alone` (permission-redacted key and log exchange). Runtime `avendb-net/tests/live.rs::a_connection_is_served_only_once_its_hello_proves_its_device` covers authentication binding. The new regression adds raw new-file refusal after an observed revocation at both ordinary and server providers, with successful pre-revocation reads using the same requester identity. It does not duplicate new-device invitation admission in `avendb/tests/gate.rs` or claim that service admission must be identical to an unrestricted local node's storage policy.
